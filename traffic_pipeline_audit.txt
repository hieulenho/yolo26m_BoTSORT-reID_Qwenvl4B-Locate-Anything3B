3.5 Load failure and parent awareness

Worker.py:320-330 catches SemanticQueueError, RuntimeError, ValueError, OSError,
writes report status=failed/error, writes worker status=failed, prints stderr and
returns exit code 2. Qwen loading/generation exceptions are wrapped as runtime
errors and normally use that path. Other exception classes can leave a traceback
and a stale lifecycle status; status handling is not universal.

run_task_realtime.ps1:253-288 synchronously runs the CV child. There is no loop
monitoring worker.HasExited or worker status while that child is running.
After CV ends, lines 290-345 request shutdown, wait up to 600 seconds, inspect
the worker exit/status and propagate failure. Timeout can force-stop the worker.

Therefore a failed worker can leave CV running with base labels until camera
termination. The parent eventually detects process failure at shutdown, not as
an immediate fail-fast interruption of live CV. Worker-side parent PID checking
does not provide reverse monitoring by the parent.
Per-event malformed answers may produce completed_with_failures and exit 0;
the worker report's failed_event_count must also be inspected.

on a frame alone is not proof of accepted VLM output.

or an ID generated inside Qwen. Qwen is instructed to return that exact ID.

realtime.py:387-394 stabilizes classes, associates optional fast proposals and
adds conservative visual color hints. It records base_detector_class_name so
semantic prompts can still receive the base class.

5.3 Event eligibility and queue behavior

realtime.py:411-449 ranks eligible tracks after minimum age=15, prioritizes
unaccepted tracks, and enqueues at most the configured successful event budget.
Age is frame_index minus first output frame; it is not a consecutive-observation
counter. Live source frame indices can skip when frames are dropped.

semantic_queue.py:206-439:
  - Does not enqueue another job while the track is processing.
  - Maintains/replaces a pending job per track, with a 90-frame normal cooldown.
  - Allows temporal evidence completion at the shorter 12-frame interval.
  - Counts pending+processing against queue capacity.
  - Full queue increments dropped_full and puts the track on enqueue cooldown.
  - Rejects low-quality crops; better crops can replace pending evidence.

Normal refresh interval can increase for accepted tracks (realtime.py:55-80):
unknown/unaccepted uses 90 frames; accepted base-only typically 4*90;
accepted fine label typically 20*90. This is sparse revalidation, not every-frame
Qwen analysis. Increasing a job cap does not make the worker process all objects
before they leave the camera view.

5.4 Crop and panel creation

semantic_queue.py:591-625 pads the original bbox by 15%, clips to the original
frame and downsizes, without upscaling, to crop_size=256 while preserving aspect.
It records the target bbox in crop-local coordinates for optional Locate use.
The crops belong to an ID because their boxes came from that ID at that frame.
The crop itself is not an independent identity recognizer.

Quality computation (518-555):
  0.30*sharpness + 0.20*brightness + 0.20*size
  + 0.20*detector_confidence + 0.10*visible_fraction.
Sharpness uses Laplacian variance normalized by 250; size uses short bbox edge/96.
visible_fraction measures crop clipping relative to the image, not an occlusion
mask. It cannot establish that the entire object is visible behind another car.

Temporal selection (558-588) retains the best crop plus evidence balancing image
quality and temporal separation. Panel creation (628-694) uses highlighted scene
context on the left (55%) and selected same-ID crops on the right.
The scene context is the event's current frame; crops can come from older frames.

5.7 Validation, memory and fusion

semantic_queue.py:1717-1747 parses answers and checks expected track IDs. Missing
or malformed per-track predictions go to failed output. Generation exceptions
requeue claims and terminate through worker failure handling.
Lines 1502-1605 enforce the closed task taxonomy and aliases, normalize names,
separate color, and check the subtype belongs to its parent. Invalid output is
not accepted merely because Qwen returned fluent text.

Lines 1783-1821 merge TemporalSemanticMemory, fuse observations and atomically
replace semantic_cache.json. Cache runtime timing describes the LAST batch, while
semantic_worker_report totals describe the worker run.

Memory schema, temporal_memory.py:110-131:
  {
    "schema_version": 2,
    "context_id": "...",
    "updated_at": "ISO timestamp",
    "summary": {"track_count":...,"observation_count":...},
    "observations": [{
      "track_id":8,"class_label":"car","confidence":0.95,
      "source":"qwen","attributes":{"color":"white"},
      "evidence_frames":[229,241,433],"evidence":"",
      "fine_label":"suv","fine_confidence":0.95,
      "fine_label_type":"subtype","taxonomy_path":[]
    }, ...]
  }
Memory load checks context_id. Merge deduplicates observations and retains up to
32 recent observations per track by default; it is not a 32-track global limit.

Fusion weights confidence by source and recency. For a candidate label:
  score = sum(confidence * source_weight * temporal_weight).
  temporal_weight uses half-life 900 frames.
  consensus = best score / all candidate scores.
  absolute confidence = best score / its accumulated weights.
  fused confidence = absolute confidence * consensus.
  margin = (best score - second score) / total scores.
Base labels require confidence>=0.75, margin>=0.10 and adequate stability when
multiple temporal groups exist. Attributes use weighted votes. The resulting
color is not accompanied by a separately calibrated color confidence in cache.

Fine acceptance excerpt, semantic_fusion.py:788-795:
  temporal_met = len(by_frame) < 2 or temporal_stability >= minimum_temporal_stability
  independent_evidence_met = len(by_frame) >= 2
  accepted = (
      confidence >= required_threshold
      and margin >= minimum_margin
      and temporal_met
      and independent_evidence_met
  )
Subtype required_threshold=0.85 here (857-870), fine margin=0.08,
fine temporal stability=0.60. Distinct frame IDs are the implementation's evidence
count; they do not prove independent human verification or two separate model calls.

5.9 Why generic class names are visible and when they change

detection/postprocessing.py:95-102 reads raw_prediction.names[class_id].
Lines 158-164 fall back to configured source names, then person for class 0 or
class_<id> for another ID. If a custom TensorRT result drops names and no map is
available, generic base labels can enter the tracker.

tracking/ultralytics_adapter.py:602-608 also has its own fallback:
  class_id = int(row[6])
  class_name = f"class_{class_id}"
  if len(row) >= 8:
      detection_index = int(row[-1])
      if 0 <= detection_index < len(detections):
          class_name = detections[detection_index].class_name

A tracker output without a valid detection-index column can thus lose a named
class even if the detection originally had one. The original project does not
create the exact no-underscore spelling class2/class7 in these locations.

When no accepted cache entry exists, SemanticCacheView.decorate():754-783 keeps
track.class_name. It stores waiting/pending in metadata, and adds "| unknown"
only for a modeled but rejected cache row. The currently reviewed live renderer
does not draw pending/waiting as text. Thus base labels alone do not distinguish
loading, waiting, queue saturation, inference failure or cache wiring failure.

For a deep color/subtype label to appear:
  a. A valid event must be created for the visible track ID.
  b. The worker must claim it, read its real images and successfully run Qwen.
  c. JSON must parse and match the expected ID and task taxonomy.
  d. Fusion must produce accepted=true and, for a subtype, fine_accepted=true.
  e. A valid color must be present or available as a compatible fast color hint.
  f. Worker and renderer must share the same cache file, and the renderer must
     refresh it while that track ID remains visible.
  g. The renderer must actually use decorated tracks, not the raw tracker outputs.

realtime.py:409-410 refreshes at frame 1 and every five frames in the default
PowerShell run. Lines 458-481 call draw_tracks with semantic_cache.decorate(...).
Qwen cache never changes MOT identities; MOT writing uses the original tracks.

LIVE formatting:
  SemanticCacheView (784-813) sets class_name to base or "base | deep".
  _semantic_detail_label (818-868) selects accepted fine label and visible color.
  draw_tracks.py:38-45 joins ID, class_name and track.confidence with " | ".
  Example shape: ID 8 | car | white suv | 0.73.
  Base may already include a fast color/proposal. track.confidence remains the
  detector/tracker score. semantic_confidence is stored in metadata, not used

DEFERRED formatting:
